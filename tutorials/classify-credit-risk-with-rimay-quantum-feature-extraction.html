Classifica il rischio di credito con la Quantum Feature Extraction Rimay di Kipu Quantum

nota

Le IBM Quantum® Functions sono una funzionalità beta disponibile solo per gli utenti dei piani IBM Quantum Premium Plan, Flex Plan e On-Prem (tramite IBM Quantum Platform API). Le funzionalità beta sono soggette a modifiche.

Stima di utilizzo: 2 minuti su un processore Nighthawk r2. (NOTA: si tratta solo di una stima. Il tuo tempo di esecuzione potrebbe variare.)

Obiettivi di apprendimento​

  • Preparare dati tabulari con colonne categoriche e numeriche per la funzione quantistica Rimay.

  • Adattare una mappatura quantistica delle feature sui dati di addestramento e mappare i dati di test nella stessa esecuzione.

  • Addestrare modelli classici sulle feature trasformate quantisticamente, da sole e combinate con le feature originali.

  • Confrontare i risultati con una baseline puramente classica.

Prerequisiti​

Prima di iniziare questo tutorial, dovresti avere familiarità con i seguenti argomenti:

  • Introduzione alle Functions

  • Classificazione supervisionata con scikit-learn

Contesto​

Molti problemi di machine learning nell'industria riguardano dataset tabulari di dimensioni piccole o medie, in cui aggiungere altri dati non è un'opzione e l'accuratezza del modello raggiunge un plateau. Il credit scoring è un esempio tipico. Un istituto di credito usa qualche decina di attributi per decidere se è probabile che il richiedente rimborserà il credito.

Rimay di Kipu Quantum aggiunge una fase di preelaborazione quantistica a una pipeline di questo tipo. Implementa l'algoritmo di estrazione quantistica delle feature controdiabatico digitalizzato [1]. Ogni feature in ingresso è mappata su un qubit. I valori delle feature e l'informazione mutua tra le feature determinano i campi locali e gli accoppiamenti di un hamiltoniano di vetro di spin. La dinamica controdiabatica fa poi evolvere il sistema quantistico verso i suoi stati a bassa energia, e i valori di aspettazione a uno e due corpi misurati alla fine diventano le nuove feature trasformate quantisticamente. Queste feature catturano correlazioni non lineari tra gli input e puoi darle in pasto a qualsiasi modello classico.

Questo tutorial usa il dataset German credit da OpenML [2], con 1000 richiedenti e 20 attributi, per addestrare un classificatore random forest. Per prima cosa stabilisci una baseline classica, poi invii i dati a Rimay e infine addestri lo stesso tipo di modello sulle feature trasformate quantisticamente, da sole e combinate con le feature originali.

Requisiti​

Prima di iniziare questo tutorial, assicurati di avere installato i seguenti pacchetti:

  • IBM Quantum Compute client (pip install qiskit-ibm-runtime)

  • Quantum Functions (pip install qiskit-ibm-catalog)

  • scikit-learn (pip install scikit-learn)

  • pandas (pip install pandas)

  • Matplotlib (pip install matplotlib)

Hai inoltre bisogno dell'accesso alla funzione Rimay dal Quantum Functions Catalog.

import matplotlib.pyplot as plt
import numpy as np
import pandas as pd
from qiskit_ibm_catalog import FunctionsCatalog
from sklearn.datasets import fetch_openml
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import (
    accuracy_score,
    f1_score,
    precision_score,
    recall_score,
    roc_auc_score,
)
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import OneHotEncoder

def train_random_forest(x, y, n_estimators, max_depth):
    """Train a random forest classifier with fixed hyperparameters."""
    model = RandomForestClassifier(
        n_estimators=n_estimators,
        max_depth=max_depth,
        min_samples_split=5,
        min_samples_leaf=1,
        max_features="sqrt",
        random_state=42,
        n_jobs=-1,
    )
    return model.fit(x, y)

def evaluate(model, x, y):
    """Return the classification metrics of a trained model on a test set."""
    y_pred = model.predict(x)
    y_proba = model.predict_proba(x)[:, 1]
    return {
        "Accuracy": accuracy_score(y, y_pred),
        "AUC": roc_auc_score(y, y_proba),
        "F1 score": f1_score(y, y_pred),
        "Precision": precision_score(y, y_pred),
        "Recall": recall_score(y, y_pred),
    }

Passo 2: Ottimizzare il problema per l'esecuzione su hardware quantistico​

Rimay costruisce e traspila i circuiti per il processore che selezioni, quindi non c'è alcun circuito da ottimizzare a mano. Specifica il numero di shot per circuito, entro i seguenti vincoli:

  • Ogni feature richiede un qubit, quindi il processore deve avere almeno tanti qubit quante sono le feature del dataset.

  • Rimay esegue un circuito per riga, righe di addestramento e di test insieme. Un singolo job può richiedere al massimo 10 milioni di esecuzioni, quindi il numero di righe per shots deve rimanere entro questo budget.

Controlla entrambi i limiti prima di inviare il job.

nota

Un job deve inoltre terminare entro 24 ore, incluso il tempo di attesa dei suoi circuiti in coda, altrimenti viene interrotto senza produrre un risultato.

Calcola la dimensione della funzione​

Ogni job viene eseguito con una dimensione della funzione, S, M o L, che seleziona le risorse di calcolo su cui gira. Per Rimay, la dimensione dipende dal numero di righe che un job mappa, righe di addestramento e di test insieme. Se richiedi una dimensione troppo piccola, il job fallisce con l'errore 4600. Per le dimensioni e i relativi limiti, consulta Dimensioni della funzione nella guida di Rimay.

La cella seguente definisce il calcolatore della dimensione. Viene eseguito sulla tua macchina, legge solo i dati che gli passi e non invia nulla.

from os import PathLike
from typing import Any, Literal, Sequence, Sized

Size = Literal["S", "M", "L"]

# Upper bounds (inclusive) in samples.
_SMALL = 2_999
_MEDIUM = 9_999

FIT_TRANSFORM, TRANSFORM, DELETE = "fit-transform", "transform", "delete"

# Which positions of input_file hold samples, per mode. The labels in
# y_train submit no circuits of their own, so they are not counted.
SAMPLE_POSITIONS = {FIT_TRANSFORM: (0, 2), TRANSFORM: (0,)}

def calculate_function_size(problem: Sequence[Sized], **kwargs: Any) -> Size:
    """Return the size ("S", "M" or "L") required to run the function."""
    metrics = _measure(problem, **kwargs)
    if _is_small(metrics):
        return "S"
    if _is_medium(metrics):
        return "M"
    return "L"

def _measure(problem: Sequence[Sized], **kwargs: Any) -> dict:
    """The samples the job submits."""
    return {"samples": count_samples(problem, kwargs.get("mode"))}

def count_samples(problem: Sequence[Sized], mode: Any) -> int:
    """Rows across the data sets of ``problem`` that carry samples."""
    if mode == DELETE:
        return 0
    if mode not in SAMPLE_POSITIONS:
        raise ValueError(f"cannot size mode {mode!r}")
    if _is_name(problem) or (
        isinstance(problem, (list, tuple))
        and any(_is_name(data) for data in problem)
    ):
        raise TypeError(
            "pass the data, not the file name: read each input_file, e.g. with "
            "pandas.read_csv, and pass the data sets in input_file order"
        )
    if not isinstance(problem, (list, tuple)):
        raise TypeError(
            "pass a list of data sets in input_file order, e.g. [x_train, y_train], "
            f"not a single {type(problem).__name__}"
        )
    return sum(
        len(problem[i]) for i in SAMPLE_POSITIONS[mode] if i < len(problem)
    )

def _is_name(value: Any) -> bool:
    """A file name or path rather than data."""
    return isinstance(value, (str, bytes, PathLike))

def _is_small(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'S'."""
    return metrics["samples"] <= _SMALL

def _is_medium(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'M'."""
    return metrics["samples"] <= _MEDIUM

Passa gli insiemi di dati nello stesso ordine dei file in input_file, insieme alla modalità dell'esecuzione:

size = calculate_function_size(
    [x_train, y_train, x_test], mode="fit-transform"
)
print(size)

Passo 3: Eseguire usando le primitive di Qiskit​

Esegui Rimay in modalità fit-transform. Adatta una mappatura quantistica delle feature su x_train.csv e y_train.csv e con essa mappa sia l'insieme di addestramento sia quello di test. L'ordine dei file in input_file è importante. Elenca le feature di addestramento, le etichette di addestramento e poi le feature di test opzionali. Passa la dimensione che hai calcolato come function_size.

job = rimay.run(
    mode="fit-transform",
    input_file=[
        "x_train.csv",
        "y_train.csv",
        "x_test.csv",
    ],  # This order matters
    backend_name=backend.name,
    shots=shots,
    function_size=size,
)
print(job.job_id)

Il risultato contiene un mapping_id, che identifica la mappatura adattata da questa esecuzione. Non ti serve in questo tutorial, perché l'insieme di test è stato mappato nella stessa esecuzione. Annota questo ID se vuoi mappare nuove righe in seguito con mode="transform". È l'unico modo per accedere alla mappatura adattata e, senza di esso, dovrai adattarne e pagarne una nuova. La mappatura è costruita per il layout dei qubit di questo processore, quindi una successiva esecuzione transform deve passare lo stesso backend_name.

mapping_id = result["mapping_id"]

Passo 4: Post-elaborare e restituire il risultato nel formato classico desiderato​

Scarica le feature trasformate quantisticamente​

Scarica i file scritti dal job, usando i nomi in output_files. Ogni nome inizia con l'ID del job, così i file di questa esecuzione restano disponibili dopo le esecuzioni successive. Passa target_name in modo che ogni file venga salvato con il proprio nome.

train_file, test_file = result["output_files"]
for file_name in (train_file, test_file):
    catalog.file_download(file_name, rimay, target_name=file_name)

xq_train = pd.read_csv(train_file).to_numpy()
xq_test = pd.read_csv(test_file).to_numpy()
print(f"Quantum-transformed features: {xq_train.shape[1]}")

Addestra sulle feature trasformate quantisticamente​

Addestra una random forest solo sulle feature trasformate quantisticamente.

quantum = train_random_forest(
    xq_train, y_train, n_estimators=900, max_depth=15
)
results["Quantum"] = evaluate(quantum, xq_test, y_test)

Addestra sulle feature classiche e quantistiche combinate​

Affianca le feature originali e quelle trasformate quantisticamente e addestra lo stesso modello sulla combinazione.

xh_train = np.hstack([x_train.to_numpy(), xq_train])
xh_test = np.hstack([x_test.to_numpy(), xq_test])

hybrid = train_random_forest(
    xh_train, y_train, n_estimators=900, max_depth=15
)
results["Hybrid"] = evaluate(hybrid, xh_test, y_test)

L'AUC misura quanto bene un modello classifica i crediti buoni sopra quelli cattivi, indipendentemente da una soglia decisionale, il che lo rende la metrica più informativa su questo dataset sbilanciato (70% di crediti buoni). Nei benchmark di Kipu Quantum, le feature trasformate quantisticamente da sole hanno raggiunto un'AUC simile a quella della baseline classica, mentre il modello ibrido, che combina entrambe, ha raggiunto la AUC e il punteggio F1 più alti. Le feature trasformate quantisticamente aggiungono quindi informazioni che le feature classiche da sole non forniscono.

Pulizia (facoltativa)​

Una mappatura adattata resta disponibile finché non la elimini. Se non vuoi mappare altri dati con essa, eliminala. Un'eliminazione non esegue alcun lavoro quantistico, non usa tempo QPU e non può essere annullata.

Conclusione​

Cosa hai realizzato​

In questo tutorial hai realizzato quanto segue:

  1. Hai preparato un dataset reale di rischio di credito con attributi categorici e numerici per l'estrazione quantistica di feature.

  2. Hai stabilito una baseline con random forest classica.

  3. Hai usato Rimay per adattare una mappatura quantistica delle feature su hardware quantistico e mappare gli insiemi di addestramento e di test in un'unica esecuzione.

  4. Hai addestrato lo stesso modello sulle feature trasformate quantisticamente e su quelle combinate, confrontandole con la baseline.

Punti chiave​

  • Rimay si inserisce in una pipeline di machine learning esistente come un ulteriore passo di preelaborazione. Mantieni la tua preparazione dei dati e il tuo modello classico.

  • Il numero di qubit limita il numero di feature di input e il numero di righe per shots limita la dimensione di un singolo job.

  • Usa come impostazione predefinita le feature trasformate quantisticamente combinate con quelle originali, perché il modello può sfruttare entrambe.

Prossimi passi​
