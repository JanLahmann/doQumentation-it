Codifica di correlazione di Pauli per ridurre i requisiti del max-cut

Stima di utilizzo: 35 minuti su un processore Eagle r3 (NOTA: questa è solo una stima. I tempi effettivi potrebbero variare.)

Obiettivi di apprendimento​

  • Comprendere i principi teorici alla base della Codifica di Correlazione di Pauli (PCE), incluso il modo in cui le stringhe di Pauli multi-corpo consentono una compressione polinomiale dei problemi di ottimizzazione classici.

  • Implementare la PCE in pratica per codificare e risolvere problemi di ottimizzazione su larga scala su hardware quantistico near-term.

Prerequisiti​

  • Algoritmi quantistici variazionali

  • QAOA e max-cut

Background​

Questo tutorial presenta la Codifica di Correlazione di Pauli (PCE) [1], un approccio progettato per codificare problemi di ottimizzazione in qubit con maggiore efficienza per il calcolo quantistico. La PCE mappa le variabili classiche dei problemi di ottimizzazione sulle correlazioni di matrici di Pauli multi-corpo, producendo una compressione polinomiale dei requisiti di spazio del problema. Grazie alla PCE, il numero di qubit necessari per la codifica è ridotto, il che la rende particolarmente vantaggiosa per i dispositivi quantistici near-term con risorse di qubit limitate. Inoltre, è dimostrato analiticamente che la PCE mitiga intrinsecamente i barren plateau, offrendo una resilienza superpolinomiale nei confronti di questo fenomeno. Questa caratteristica integrata consente prestazioni senza precedenti nei solver di ottimizzazione quantistica.

Panoramica​

L'approccio PCE consiste di tre passi principali, come illustrato nella Figura 1 di [1] qui sotto:

  1. Codificare il problema di ottimizzazione in uno spazio di correlazione di Pauli.
  2. Risolvere il problema utilizzando un solver di ottimizzazione quantistico-classico.
  3. Decodificare la soluzione riportandola nello spazio di ottimizzazione originale. L'approccio PCE è adattabile a qualsiasi solver di ottimizzazione quantistica in grado di elaborare matrici di correlazione di Pauli. Nella Figura 1 di [1], il problema del max-cut viene utilizzato come esempio per illustrare l'approccio PCE. Il problema del max-cut con m=9m=9m=9 nodi è codificato in uno spazio di correlazione di Pauli, rappresentando il problema di ottimizzazione come una matrice di correlazione — nello specifico, correlazioni tra matrici di Pauli a due corpi su n=3n=3n=3 qubit (Q1,Q2,Q3)(Q_1, Q_2, Q_3)(Q1​,Q2​,Q3​). I colori dei nodi indicano la stringa di Pauli utilizzata per ciascun nodo codificato. Ad esempio, il nodo 1, che corrisponde alla variabile binaria x1x_1x1​, è codificato dal valore di aspettazione di Z1⊗Z2⊗I3Z_1 \otimes Z_2 \otimes I_3Z1​⊗Z2​⊗I3​, mentre x8x_8x8​ è codificato da I1⊗Y2⊗Y3I_1 \otimes Y_2 \otimes Y_3I1​⊗Y2​⊗Y3​. Questo corrisponde a comprimere le mmm variabili del problema in n=O(m1/2) n = O(m^{1/2})n=O(m1/2) qubit. Più in generale, le correlazioni a kkk corpi consentono compressioni polinomiali di ordine kkk, con k>1k>1k>1. L'insieme di Pauli scelto comprende tre sottoinsiemi di stringhe di Pauli mutuamente commutanti, permettendo che tutte le mmm correlazioni vengano stimate sperimentalmente con sole tre impostazioni di misurazione.

Viene costruita una funzione di perdita L\mathcal{L}L di valori di aspettazione di Pauli che imita la funzione obiettivo originale del max-cut. La funzione di perdita viene quindi ottimizzata utilizzando un solver di ottimizzazione quantistico-classico, come il Variational Quantum Eigensolver (VQE).

Una volta completata l'ottimizzazione, la soluzione viene decodificata riportandola nello spazio di ottimizzazione originale, producendo la soluzione ottimale del max-cut.

Requisiti​

Prima di iniziare questo tutorial, assicurati di aver installato quanto segue:

  • Qiskit SDK v1.0 o versione successiva, con supporto per la visualizzazione
  • Qiskit Runtime v0.22 o versione successiva (pip install qiskit-ibm-runtime)
  • Addon Qiskit Optimization Mapper (pip install qiskit-addon-opt-mapper)

def make_cut_evaluator(problem):
    """Return a function that maps a 0/1 node assignment to its cut value.

    The objective of the max-cut ``OptimizationProblem`` is the cut value
    itself, and ``problem.objective.evaluate`` computes it for one
    assignment. The swap search in Step 4 evaluates one candidate
    assignment per edge, so pull the objective's coefficients out once
    and evaluate them as a sparse matrix product instead.
    """
    quadratic = problem.objective.quadratic.coefficients.tocsr()
    linear = problem.objective.linear.to_array()
    constant = problem.objective.constant

    def evaluate_cut(bits):
        x = np.asarray(bits, dtype=float)
        return int(round(constant + linear @ x + x @ (quadratic @ x)))

    return evaluate_cut

Passo 1: Mappare gli input classici in un problema quantistico​

Il problema del max-cut​

Il problema del max-cut è un problema di ottimizzazione combinatoria definito su un grafo G=(V,E)G = (V, E)G=(V,E), dove VVV è l'insieme dei vertici ed EEE è l'insieme degli spigoli. L'obiettivo è partizionare i vertici in due insiemi, SSS e V∖SV \setminus SV∖S, in modo tale che il numero di spigoli tra i due insiemi sia massimizzato. Per una descrizione dettagliata del problema del max-cut, fai riferimento al tutorial Algoritmo di ottimizzazione approssimata quantistica. Il problema del max-cut viene utilizzato anche come esempio nel tutorial Tecniche avanzate per QAOA. In quei tutorial, l'algoritmo QAOA viene utilizzato per risolvere il problema del max-cut.

Codifichiamo il grafo con 100 nodi in correlazioni tra matrici di Pauli a due corpi su nove qubit (vedi la spiegazione sotto). Il grafo è rappresentato come una matrice di correlazione, dove ogni nodo è codificato da una stringa di Pauli. Ora, codifichiamo il grafo in un'Hamiltoniana utilizzando la PCE. Dividiamo i nodi in tre insiemi: S1S_1S1​, S2S_2S2​, e S3S_3S3​. Poi, codifichiamo i nodi in ciascun insieme utilizzando rispettivamente le stringhe di Pauli con XXX, YYY, e ZZZ. Dobbiamo estrarre una relazione tra il numero di nodi e di qubit di cui avremo bisogno per codificare tutti i nodi. Utilizzando tutte le possibili permutazioni per la codifica si ottiene:

m=3(nk).m=3\binom{n}{k}.m=3(kn​).

m=32n(n−1).m = \frac{3}{2} n(n-1).m=23​n(n−1).

def build_pauli_correlation_encoding(pauli, node_list, n, k=2):
    pauli_correlation_encoding = []
    for idx, c in enumerate(combinations(range(n), k)):
        if idx >= len(node_list):
            break
        paulis = ["I"] * n
        paulis[c[0]], paulis[c[1]] = pauli, pauli
        pauli_correlation_encoding.append(("".join(paulis)[::-1], 1))

    hamiltonian = []
    for pauli, weight in pauli_correlation_encoding:
        hamiltonian.append(SparsePauliOp.from_list([(pauli, weight)]))

    return hamiltonian

pauli_correlation_encoding_x = build_pauli_correlation_encoding(
    "X", node_x, num_qubits

    "Y", node_y, num_qubits
)
pauli_correlation_encoding_z = build_pauli_correlation_encoding(

Passo 2: Ottimizzare il problema per l'esecuzione su hardware quantistico​

Circuito quantistico​

Qui lo stato ∣ψ⟩|\psi \rangle∣ψ⟩ è parametrizzato con θ\mathbf{\theta}θ, e ottimizziamo questi parametri θ\mathbf{\theta}θ usando un approccio variazionale. Questo tutorial utilizza l'ansatz efficient_su2 per il nostro algoritmo variazionale, grazie alle sue capacità espressive e alla facilità di implementazione. Utilizziamo anche la funzione di perdita rilassata, che verrà introdotta più avanti in questo tutorial. Di conseguenza, possiamo affrontare problemi su larga scala con meno qubit e profondità di circuito inferiori.

Funzione di perdita​

Per la funzione di perdita L\mathcal{L}L, usiamo un rilassamento della funzione obiettivo del max-cut come descritto in [1], definita come V(x)≔∑(i,j)∈EWi,j(1−xixj)\mathcal{V}(\mathbf{x}) \coloneqq \sum_{(i, j) \in E} W_{i, j}(1-x_i x_j)V(x):=∑(i,j)∈E​Wi,j​(1−xi​xj​). Qui, Wi,jW_{i, j}Wi,j​ indica il peso dell'arco (i,j)(i, j)(i,j), e xix_ixi​ rappresenta la partizione del nodo iii. La funzione di perdita L\mathcal{L}L è data da:

L≔∑(i,j)∈EWi,jtanh(α⟨∏i⟩)tanh(α⟨∏j⟩)+L(reg)\mathcal{L}\coloneqq \sum_{(i, j) \in E} W_{i, j} \text{tanh} (\alpha \langle\prod_i \rangle) \text{tanh} (\alpha \langle\prod_j \rangle) + \mathcal{L}^{(\text{reg})}L:=∑(i,j)∈E​Wi,j​tanh(α⟨∏i​⟩)tanh(α⟨∏j​⟩)+L(reg),

dove la funzione obiettivo del max-cut è sostituita dalle tangenti iperboliche regolari dei valori di aspettazione delle stringhe di Pauli che codificano i nodi. Il termine di regolarizzazione L(reg)\mathcal{L}^{(\text{reg})}L(reg) e il fattore di riscalatura α\alphaα, proporzionale al numero di qubit, sono introdotti per migliorare le prestazioni del solver.

Il termine di regolarizzazione è definito come:

L(reg)\mathcal{L}^{(\text{reg})}L(reg) è definito come L(reg)≔βν[1m∑i∈Vtanh(α⟨∏i⟩)2]2\mathcal{L}^{(\text{reg})} \coloneqq \beta \nu \lbrack \frac{1}{m} \sum_{i \in V} \text{tanh} (\alpha \langle\prod_i \rangle)^2 \rbrack ^2L(reg):=βν[m1​∑i∈V​tanh(α⟨∏i​⟩)2]2

dove β=1/2\beta=1/2β=1/2, ν=∣E∣/2+(m−1)/4\nu = |E|/2 + (m -1) /4ν=∣E∣/2+(m−1)/4, ∣E∣|E|∣E∣ è il numero di archi e mmm è il numero di nodi nel grafo.

def loss_func_estimator(x, ansatz, hamiltonian, estimator, graph):
    """
    Calculates the specified loss function for the given ansatz, Hamiltonian,
    and graph.

    The expectation values of each Pauli string in the Hamiltonian are first
    obtained by running the ansatz on the quantum backend. These
    expectation values are then passed through the nonlinear function
    tanh(alpha * prod_i). The loss function is
    subsequently computed from these transformed values.
    """
    job = estimator.run(
        [
            (ansatz, hamiltonian[0], x),
            (ansatz, hamiltonian[1], x),
            (ansatz, hamiltonian[2], x),
        ]
    )
    result = job.result()

    # calculate the loss function
    node_exp_map = {}
    idx = 0
    for r in result:
        for ev in r.data.evs:
            node_exp_map[idx] = ev
            idx += 1

    loss = 0
    alpha = num_qubits
    for edge0, edge1 in graph.edge_list():
        loss += np.tanh(alpha * node_exp_map[edge0]) * np.tanh(
            alpha * node_exp_map[edge1]
        )

    regulation_term = 0
    for i in range(len(graph.nodes())):
        regulation_term += np.tanh(alpha * node_exp_map[i]) ** 2
    regulation_term = regulation_term / len(graph.nodes())
    regulation_term = regulation_term**2
    beta = 1 / 2
    v = len(graph.edges()) / 2 + (len(graph.nodes()) - 1) / 4
    regulation_term = beta * v * regulation_term

    loss = loss + regulation_term

    global experiment_result
    print(f"Iter {len(experiment_result)}: {loss}")
    experiment_result.append({"loss": loss, "exp_map": node_exp_map})
    return loss

Passo 4: Post-elaborazione e restituzione del risultato nel formato classico desiderato​

Le partizioni dei nodi sono determinate valutando il segno dei valori di aspettazione delle stringhe di Pauli che codificano i nodi. Un valore di aspettazione non negativo assegna al nodo il valore 1, e un valore di aspettazione negativo assegna 0. Il metodo interpret di Maxcut decodifica poi questa assegnazione nei due insiemi di nodi.

# Decode the node assignment from the iteration with the lowest loss.
# If the expectation value is non-negative, the node is assigned 1,
# otherwise it is assigned 0.
def get_bits(experiment_result):
    best_index = min(
        range(len(experiment_result)),
        key=lambda i: experiment_result[i]["loss"],
    )
    exp_map = experiment_result[best_index]["exp_map"]
    bits = [1 if exp_map[i] >= 0 else 0 for i in range(len(exp_map))]
    return bits, best_index

Una volta completato l'addestramento, eseguiamo un ciclo di ricerca con scambio di un singolo bit per migliorare la soluzione come passo di post-elaborazione classica. In questo processo, scambiamo le partizioni di due nodi e valutiamo la dimensione del taglio. Se la dimensione del taglio migliora, manteniamo lo scambio. Ripetiamo questo processo per tutte le possibili coppie di nodi connessi da un arco.

# Swap the partitions and calculate the cut size

def swap_partitions(graph, cur_bits, evaluate_cut):
    best_cut = 0
    best_bits = []
    for edge0, edge1 in graph.edge_list():
        swapped_bits = cur_bits.copy()
        swapped_bits[edge0], swapped_bits[edge1] = (
            swapped_bits[edge1],
            swapped_bits[edge0],
        )
        cut_size = evaluate_cut(swapped_bits)
        if best_cut < cut_size:
            best_cut = cut_size
            best_bits = swapped_bits
    return best_cut, best_bits

best_cut, best_bits = swap_partitions(graph, cur_bits, evaluate_cut)
